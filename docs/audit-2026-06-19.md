## Findings (prioritized)

### SEC-1 — `ProviderTransport` bypasses the SSRF guard (HIGH)
**File:** `packages/nodes/noodle_nodes/integrations_v2/transport.py:177-206`

The shared transport for **all 36 v2 integration providers** issues
`requests.request(...)` directly, and `ProviderTransport.url()` passes through
any absolute `http(s)://` value untouched. It never calls
`assert_public_http_url` / `safe_request`, even though that DNS-rebinding-aware
helper already exists in the same package.

Several providers build the host from **user-supplied credential fields**, so a
tenant can point them at internal/metadata addresses:
- `gitlab` → `server_url` (self-hosted instances)
- `supabase` → `project_url`
- `woocommerce` → `store_url`
- `shopify` → shop domain, `jira` → `site`, `mailchimp` → datacenter, etc.

**Impact:** authenticated SSRF from the worker's network position
(`http://169.254.169.254/...`, internal services) across the entire v2 node
surface. This is the single highest-leverage fix: one chokepoint protects dozens
of nodes.

**Fix:** route `ProviderTransport.request` through `safe_request` (inject
`requests.request` as `request_fn`), or call `assert_public_http_url(url)` before
each attempt. Add a regression test that a `server_url` of `127.0.0.1` /
`169.254.169.254` is rejected.

### SEC-2 — Legacy integration nodes call `requests` raw (MEDIUM)
**File:** `packages/nodes/noodle_nodes/saas.py:180` (`jira_create_issue`), and
peers in `saas.py` / `communication.py`

`jira_create_issue` does `requests.post(f"https://{site}/rest/api/3/issue", ...)`
with a user-controlled `site` and no guard — same SSRF class as SEC-1 for the
pre-v2 nodes. Sweep: `saas.py`, `communication.py`, `storage.py`,
`integrations.py` (the last partially adopts `safe_request`).

**Fix:** same remedy — funnel through `safe_request`. Best done as part of SEC-3.

### SEC-3 — Three independent SSRF implementations (MEDIUM, architectural)
**Files:** `http_security.py` (`assert_public_http_url`),
`file_nodes.py:479` (`_ssrf_safe_fetch`), and `transport.py` (no real guard;
`_safe_url` is only log-redaction).

Three partial implementations mean coverage drifts and the strongest one
(`safe_request`, with per-redirect-hop revalidation and credential stripping)
isn't the one most nodes use. Consolidate to a single egress module that every
HTTP-capable node imports. This is the root cause behind SEC-1 and SEC-2.

### SEC-4 — `postgres_query` / DB nodes allow arbitrary connection hosts (LOW–MEDIUM)
**File:** `packages/nodes/noodle_nodes/postgres_nodes.py:72`

`psycopg.connect(connection_url)` with a user-supplied URL is protocol-level
SSRF (connect to any internal Postgres). Acceptable in single-tenant; for hosted
multi-tenant, gate DB-connection hosts the same way as HTTP egress, or rely on
`sandbox_network` egress isolation and document that dependency explicitly.

### PERF-1 — Adopting `safe_request` adds a `getaddrinfo` per request (LOW, accept)
When SEC-1/2 land, each request resolves DNS to validate. That's the correct
trade (rebinding safety) and the helper deliberately doesn't cache verdicts. Keep
it; just be aware it adds a few ms to provider calls. No mitigation needed.

## Architecture observations

1. **Single egress chokepoint is the most valuable refactor.** All node network
   I/O (HTTP + DB + file fetch) should pass one policy module. It fixes SEC-1/2/3
   at once and gives you one place to add per-org allow/deny lists, egress
   metering, and proxy enforcement later.
2. **Worker reuses the full API import graph** (`worker_main.py` imports the
   `app` package). Pragmatic, but startup cost and dependency surface scale with
   the API. Consider extracting a slim execution package if worker cold-start or
   image size becomes a concern.
3. **Node library growth needs a guardrail.** 36 v2 providers + ~40 new
   uncommitted node files landed without the shared transport enforcing egress
   safety. A single base class / lint rule ("node HTTP must go through
   `safe_request`") would prevent the next SEC-1 from being reintroduced.
4. **Migration churn** — 55 Alembic revisions on a pre-1.0 project. Squash to a
   clean baseline before the OSS/GA release; verify none are irreversible.

---

## Recommended order of work

1. **SEC-1** — wrap `ProviderTransport` in `safe_request` (highest impact,
   contained change, add tests). 
2. **SEC-3** — consolidate the three SSRF helpers into one egress module;
   **SEC-2** falls out of this.
3. **O2 / S1 / A1** — small, already-scoped wins.
4. **SEC-4** — decide hosted-vs-single-tenant policy for DB/host egress.
5. Architectural: single egress chokepoint + a node-author lint rule.

## Resolution — implemented 2026-06-19 (TDD)

All security findings and both code-level architecture recommendations are
done. Each change was test-first (red → green) and the full nodes suite (825
passed) + affected API tests stay green.

**Egress policy (the keystone).** `http_security.private_egress_allowed()` reads
`NOODLE_ALLOW_PRIVATE_EGRESS`. The default follows the deployment model —
`_worker_env()` sets it to `0` under multi-tenancy (block internal/metadata) and
`1` for single-tenant self-hosted (so Ollama/localhost, a VPC database, and
self-hosted integrations work out of the box); an explicit env var overrides
either way. This avoids the trap where a blanket hard-block breaks legitimate
self-hosted private targets. Documented in `.env.example`.

- **SEC-1 ✅** `ProviderTransport.request` now routes every call (all 36 v2
  providers) through `safe_request`; SSRF fails fast and is never retried.
- **SEC-2 ✅** Converted the user-host fetchers: `jira_create_issue`,
  Elasticsearch search (`storage.py`), AI HTTP tool (`ai_v2/tools.py`),
  URL document loader, Qdrant vector store, RSS feed trigger, sitemap crawl.
- **SEC-3 ✅** One canonical guard. `assert_public_http_url` and the
  DNS-pinning `file_nodes._ssrf_safe_fetch` both honour the shared policy; added
  scheme-agnostic `assert_public_host` reused by HTTP and DB nodes.
- **SEC-4 ✅** Postgres nodes call `_assert_connection_allowed` (parses the DSN
  host, applies `assert_public_host`) before connecting.
- **ARCH guardrail ✅** `test_node_egress_policy.py` fails if a node makes a raw
  `requests.<verb>()` call without the guard, unless it's on a documented
  fixed-/model-endpoint allowlist (Anthropic, OpenAI, embeddings, Pushover).
- **O2 / A1 ✅ (already in tree)** `_all_workflows()` already filters
  `active OR draft_graph`; typed `ServiceError`s + the `main.py` handler +
  `runner.py` adoption already exist.
- **S1 — moot.** `decrypt_data()` has no production execution-path caller; the
  credential/SSH path uses the strict-capable `decrypt_credential`.

**Still deliberately deferred (need a separate, deliberate effort):**
- **Squash 55 migrations** — destructive and deployment-affecting; do it as a
  planned pre-GA baseline cut, not mid-stream.
- **Worker ↔ API decoupling** — large refactor; revisit if worker cold-start or
  image size becomes a real constraint.
