## Phase 0 — Security 8.0 → 10  *(do first; smallest change, biggest risk reduction)*

### 0.1 Gate the Docker nodes (SEC-A) — **S**
- **Gap:** `docker_run_container`, `docker_stop_container`, `docker_list_containers` appear in no list in `unsafe_nodes.py`; arbitrary container execution (root-equivalent) faces no deploy-time approval gate.
- **Work:** add `docker_run_container` + `docker_stop_container` to `UNCONDITIONAL_UNSAFE` (kind `execute_command`); add `docker_list_containers` to a read-only egress finding (or `UNCONDITIONAL_UNSAFE` if it exposes host state).
- **Files:** `apps/api/app/services/unsafe_nodes.py`.
- **Tests:** extend `apps/api/tests/test_unsafe_nodes*.py` — a graph with each Docker node yields a finding; a deployment activation with policy `require_approval` is rejected without `approve_unsafe_nodes`.
- **10/10 bar:** every node that runs arbitrary code/containers or opens caller-supplied egress is classified; a test enumerates the registry and asserts no "executes code / raw egress" node is missing from the gate.

### 0.2 Route `llm.py` user endpoints through `safe_request` (SEC-B) — **M**
- **Gap:** Azure (`azure_endpoint`) and custom `base_url` (openai_compatible) chat calls use raw `requests.post` — no per-hop redirect re-validation, DNS-rebinding socket patch, or credential stripping.
- **Work:** wrap those calls in `http_security.safe_request`; keep the `ollama` localhost default working via `NODYRA_ALLOW_PRIVATE_EGRESS` (document it). Audit the other ~8 `requests.post` sites in `llm.py`/`ai_extra.py` and route every caller-supplied URL through `safe_request`.
- **Files:** `packages/nodes/nodyra_nodes/llm.py`, `ai_extra.py`.
- **Tests:** `packages/nodes/tests/` — a private/loopback `base_url`/`azure_endpoint` is rejected (unless egress allowed); a 302→private redirect is blocked; credentials are stripped on cross-origin redirect.
- **10/10 bar:** a repo-wide test/lint asserts **no** node module calls `requests`/`httpx` directly on a caller-supplied URL without `safe_request` (allowlist the fixed-host provider calls).

**Phase 0 acceptance:** Security dimension = 10 when (a) unsafe-gate coverage is enumerated-and-tested, and (b) the "no unguarded egress" lint passes across `packages/nodes`.

## Phase 1 — Data flow 8.5 → 10

### 1.1 Unified `resolve_ref` read façade — **M**
- **Gap:** offload-marker resolution is now correct but scattered across ~10 call sites; a future new reader (or a new ref type) can silently reintroduce the raw-marker bug.
- **Work:** add `app/services/data_ref.py::resolve_ref(value)` that resolves output-store markers **and** (future) artifact/dataset refs at read boundaries; route the existing 10 sites through it; keep `resolved_output` as a thin alias for back-compat.
- **Files:** new `apps/api/app/services/data_ref.py`; update `runs.py`, `run_resume.py`, `schemas.py`, `mcp/tools.py`, `triggers.py`, `agentic_builder.py`.
- **Tests:** a guard test that greps the API tree for `.output` reads from ORM `NodeRun` and asserts each is wrapped (AST-level check, not string match), so a new unwrapped reader fails CI.
- **10/10 bar:** exactly one resolution chokepoint; the guard test makes regressions impossible to merge.

### 1.2 Offload observability — **S**
- **Gap:** offload writes are best-effort and silent on failure (fall back to inline).
- **Work:** structured log + counter metric on offload write failure and on marker-read fallback; surface in the existing metrics/health path.
- **Files:** `apps/api/app/services/output_store.py`, `run_persistence.py`, metrics module.
- **Tests:** a forced write failure increments the counter and logs once; the run still succeeds inline.
- **10/10 bar:** an operator can alert on offload degradation; no silent data-plane failure.

### 1.3 Typed-envelope round-trip completeness — **S**
- **Work:** property-based test (`hypothesis`) round-tripping the typed serializer across datetime/Decimal/bytes/tuple/set/nested/DataFrame; document unrestorable-object semantics.
- **Files:** `packages/core/tests/test_serialization*.py`.
- **10/10 bar:** serializer round-trip is property-tested, not example-tested.

**Phase 1 acceptance:** Data flow = 10 when resolution is single-chokepoint + CI-guarded, offload is observable, and serialization is property-tested.

## Phase 2 — AI builder catalog 6.5 → 10

### 2.1 Manifest-derived catalog with param signatures — **M/L**
- **Gap:** `node_catalog_for_prompt` emits only `id - name`; detailed params exist for ~64/512 nodes, so the LLM guesses params for ~87% of the catalog.
- **Work:** generate the catalog from `NodeManifest` (params: name/type/required/choices; ports: name/data_kind; `usable_as_tool`) within the char budget, tiered by relevance so the budget spends on likely nodes first. Keep `_NODE_REGISTRY` only for priority ordering, not as the param source of truth.
- **Files:** `apps/api/app/services/ai_builder.py`.
- **Tests:** generated catalog for a sample includes required-param signatures for nodes previously name-only; a golden test asserts an AI-drafted workflow validates against manifests (required params present, port kinds compatible).
- **10/10 bar:** the AI builder can correctly configure any node in the catalog from manifest data alone; param-fidelity golden test passes for a representative node set.

**Phase 2 acceptance:** AI catalog = 10 when param signatures are manifest-driven for the full catalog and validated by a golden workflow test.

## Phase 3 — Artifact / result storage 8.5 → 10

### 3.1 At-rest protection + retention for the output store — **M**
- **Gap:** offloaded output files inherit artifact-store path safety but lack explicit at-rest encryption option and retention/GC tied to run pruning.
- **Work:** optional at-rest encryption (reuse artifact backend crypto if present); wire output-store GC into `retention.prune_old_runs` so offloaded files are deleted with their runs.
- **Files:** `output_store.py`, `retention.py`, `artifact_backends.py`.
- **Tests:** pruning a run deletes its offloaded files; Local/S3 backend parity test for write/read/delete/signed-url.
- **10/10 bar:** no orphaned offload files; storage tier has encryption-at-rest parity with the artifact layer.

**Phase 3 acceptance:** Storage = 10 when output-store lifecycle (create→read→GC) and at-rest protection match the artifact layer, backend-parity-tested.

## Phase 4 — Performance / scalability 8.0 → 10

### 4.1 Benchmark harness + perf gate — **M**
- **Work:** micro-benchmarks for scheduler fan-out, serialization of large payloads, offload write/read, DatasetRef expand; record baselines; CI perf-regression gate (warn, not block).
- **Files:** `packages/core/tests/bench/` (or `pytest-benchmark`).
- **10/10 bar:** hot-path performance is measured with tracked baselines.

### 4.2 Streaming path for very-large outputs — **M**
- **Gap:** outputs >10 MiB are truncated to a preview; there's no stream-to-artifact escalation for legitimately large results.
- **Work:** when an output exceeds the cap, escalate to an `ArtifactRef` (stream to backend) instead of truncating, when the node opts in; keep truncation as the default safety.
- **Files:** `run_persistence.py`, `serialization.py`, `artifacts.py`.
- **Tests:** a >10 MiB output escalates to an artifact and is retrievable; the cap still bounds inline/DB storage.
- **10/10 bar:** large results are retained (as artifacts) rather than silently lost, without unbounded DB/row growth.

**Phase 4 acceptance:** Performance = 10 when hot paths are benchmarked with baselines and large-output handling has a lossless escalation path.

## Phase 6 — Node UX 8.0 → 10

### 6.1 Large-output UX — **M**
- **Gap:** offloaded/truncated outputs need a first-class viewer affordance.
- **Work:** `PortDataViewer` lazily fetches an offloaded output on demand with a "download full" action and a clear "truncated / stored" badge; the run-detail endpoint gains an opt-in "don't inline, give me a fetch URL" mode so huge outputs don't bloat the initial response.
- **Files:** `apps/web/src/editor/.../PortDataViewer.tsx`, `apps/api/app/routers/runs.py`, `schemas.py`.
- **Tests:** frontend test for the truncated/stored states; API test for the fetch-URL mode.
- **10/10 bar:** large outputs are viewable, downloadable, and never degrade run-detail load; a11y pass on the palette + viewer.

**Phase 6 acceptance:** UX = 10 when large-output viewing is first-class and the palette/viewer pass a11y.
