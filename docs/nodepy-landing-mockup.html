Name recommendation

Use NodePy Studio for the page, not plain NodePy.

Plain NodePy communicates the product quickly, but it is already used by other Python projects. NodePy Studio keeps the intent and gives the product a clearer category.

Recommended

NodePy Studio

Best balance: Python-native, workflow-node aware, and productized. "Studio" makes it feel like a builder, not just a library.

Short mark

NodePy

Strong and literal, but the highest collision risk. Good as the shorthand if the full product name is NodePy Studio.

Alternative

PyFlow

Clear workflow signal and easier to say. Less distinctive than Noodle, but more obvious to Python automation buyers.

Product story

Visual workflows without giving up real Python.

The landing page should sell what makes the platform different: every node can be a Python function, every run is observable, and production controls are part of the workflow model.

Node canvas for engineers

Build flows visually, keep parameters typed, and inspect the graph without hiding the underlying code.

Python runtime control

Run pandas, boto3, DuckDB, and internal libraries in environment-aware Python workers.

Production from draft

Ship releases with credentials, audit logs, retries, schedules, webhooks, artifacts, and run history.

import pandas as pd

def run(event, artifacts, creds):
    rows = pd.DataFrame(event["rows"])
    rows["net"] = rows.amount - rows.fee
    clean = rows[rows.net > 0]

    # Return a durable table handle, not a huge JSON blob.
    return artifacts.dataset(clean)
Landing page stance

Lead with the product UI, then prove the Python-native runtime.

The current Noodle story is strong, but the page should show the workflow editor immediately. The clearest buyer message is: build like a visual automation tool, run like a Python platform.
