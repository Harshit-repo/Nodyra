## 1. Bugs Found & Fixed

### B2 — Missing unique constraint on `is_global` allowed duplicate global environments
**File:** `apps/api/app/models.py:142-149`
**Severity:** Medium | **Status:** ✅ Fixed

`_ensure_global_environment` (main.py) catches `IntegrityError` on insert, but the `Environment` model had no unique constraint on `is_global`. Two concurrent API replicas could both see no global env and both insert — producing two rows instead of one. The IntegrityError catch was dead code.

**Fix:** Added a partial unique Postgres index `uq_environment_is_global` with `postgresql_where=text("is_global IS TRUE")` so exactly one row can have `is_global=True`. The existing `IntegrityError` handler now actually fires.

### B5 — Redis event publish silently fell back to in-process, losing events in split topologies
**File:** `apps/api/app/services/events.py:132-162`
**Severity:** High | **Status:** ✅ Fixed

`_async_publish` tried Redis once, and on any failure fell back to the in-process buffer. In split-topology mode (`dispatch_role != inline`), WebSocket subscribers connect to the API replica and read events from Redis — the worker's in-process buffer is unreachable, so the event is silently lost. The old `except Exception` log line said "using in-process" which was misleading (there are no in-process subscribers in split mode).

**Fix:** Added one retry (100ms delay) before final fallback. The retry log is a warning; the final failure log is `exception`-level and explicitly states the event won't reach cross-process subscribers. The in-process fallback is preserved for single-process deployments where it's genuinely useful.

### B6 — Pre-generated `run_id` could collide with an existing run
**File:** `apps/api/app/services/runner.py:505-515`
**Severity:** Medium | **Status:** ✅ Fixed

Webhook raw-body capture pre-generates a run ID via `uuid4().hex` to write artifact files under `runs/<run_id>/` before the DB row exists. The ID was assigned directly to `run.id` with no collision check. A PK collision would surface as an opaque `IntegrityError` → 500.

**Fix:** Before assigning the pre-generated ID, query `session.get(Run, run_id)`. On collision, log a warning and clear `run_id` so the model auto-generates a fresh one. UUID4 collision is astronomically unlikely, so this is defense-in-depth.

### `_ensure_global_environment` missing `run_as_system()` for multi-tenant correctness
**File:** `apps/api/app/main.py:70-101`
**Severity:** Medium | **Status:** ✅ Fixed

The function selects environments matching `is_global=True` to check whether one exists. With multi-tenancy enabled, the ORM tenancy filter (`active_org_id()` falls back to `DEFAULT_ORG_ID` when the ContextVar is unset) scopes the SELECT to `org_id="default"`. Every non-default org would appear to have no global environment — even though a global env for the default org already exists. Contrast with `_mark_interrupted_runs` which correctly uses `run_as_system()`.

**Fix:** Wrapped the entire function body in `with run_as_system():` so the org filter is bypassed and the function sees all environments regardless of tenant.

## 2. False Positives (code already correct)

### B1 — `_FATAL_ERRORS` block supposedly unreachable
**File:** `packages/core/noodle/engine/node_exec.py:554-556`

Python matches `except` clauses in declaration order. `_FATAL_ERRORS = (MemoryError, RecursionError, SystemError)` appears at L554, *before* the generic `except Exception` at L557. Since all three are subclasses of `Exception`, the specific clause is checked first and takes priority when they match. The block is reachable for those three types. No change needed.

### B3 — `contextlib.suppress(asyncio.CancelledError)` in shutdown
**File:** `apps/api/app/main.py:350-352`

This is standard asyncio shutdown boilerplate. The loop calls `task.cancel()` then awaits the task; the expected outcome is `CancelledError`. If a nested subtask raised a different `CancelledError`, the parent task would already have been cancelled (we just called `cancel()` on it). Suppressing the expected cancellation is correct.

### B4 — Queue rollback on local capacity miss leaking `attempts`
**File:** `apps/api/app/services/queue.py:820-827`

`lease()` does `session.flush()` (not `commit()`). The dispatch loop's `session.rollback()` on capacity miss correctly undoes the flush — `attempts` is not visible to other sessions. The entry returns to `queued` with its original attempt count.

## 3. Known Remaining Fragility

### `run.id = run_id` pattern — variable shadowing and orphaned artifacts
**File:** `apps/api/app/services/runner.py:502-538`
**Severity:** Low

The function parameter `run_id` is reassigned twice:
1. **L507** (B6 fix) — set to `None` on collision
2. **L538** — overwritten to `run.id` after `session.flush()` picks up the auto-generated value

The pattern works correctly (both flows converge on a confirmed ID at L538) but is subtle. A future refactor that uses `run_id` between L506 and L538 expecting the *input* value could be surprised.

**Residual risk:** If a pre-generated `run_id` collides, the artifact files already written under `runs/<old_run_id>/` are orphaned — the new run uses a different auto-generated ID. This only matters for webhook raw-body capture during a UUID collision (astronomically unlikely).

**Future fix:** Rename the parameter to `pre_run_id` and keep a separate `run_id: str` local for the confirmed ID. On collision, move/rename the artifact directory from the old ID to the new one if a directory exists.
