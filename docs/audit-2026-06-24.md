# Noodle Platform — Production-Grade Audit Report
**Date:** 2026-06-24  
**Audited branch:** `feat/node-expansion-plan`  
**Auditor:** Claude Sonnet 4.6 (Principal Engineer / Staff Architect / Security Auditor)  
**Scope:** Full-stack — backend API, workflow engine, node system, frontend, database, DevOps, security, testing, performance, product

---

## Executive Summary

Noodle is a well-architected, genuinely ambitious workflow platform. The codebase shows sophisticated thinking in many areas: multi-layer multi-tenancy (ORM filter + RLS + ContextVar GUC), a DEK/KEK envelope encryption scheme for credentials, a correct fair-queue dispatch system, clean CSRF/cookie handling, and structured logging. The developer has done real security work that is uncommon at this stage.

However, **Noodle is not production-ready for multi-tenant hosted deployment** and has several P0 issues that must be resolved first. The core problems are:

1. **The Code node sandbox is not a real security boundary.** Any user with editor access can escape it with `import os`.
2. **Three CI gates that should block merges are all advisory** — frontend tests don't run at all, the Postgres test lane is `continue-on-error`, and all security scanning is non-blocking.
3. **Two MCP tools bypass the multi-tenant org filter** using `session.get()` which skips the `do_orm_execute` ORM event.
4. **The production web image uses Vite's dev server**, not a built static asset served by nginx.
5. **`deploy/.env` with real secrets is likely being baked into Docker images** via `COPY . .`.
6. **Two new GitHub sync tables are missing RLS policies**, and the webhook secret is stored in plaintext.

For single-tenant self-hosted deployment the risk profile is substantially lower — most multi-tenancy bypass issues become self-inflicted. However, the CI/CD, sandbox, and deployment issues affect all deployment models.

**Verdict:** Fix the 8 P0s and 22 P1s before inviting external users. The platform will be production-ready for self-hosted single-tenant after that sprint. Multi-tenant hosted requires additional work on true sandboxing.

**Monorepo structure:** `uv` Python workspace with per-package `pyproject.toml`. Backend is FastAPI + SQLAlchemy 2.x async + Alembic. Frontend is Vite + React + ReactFlow. Deployment supports Docker Compose and Helm.

**Multi-tenancy model:** ORM `do_orm_execute` event filters all SELECT queries by `org_id` ContextVar. Postgres RLS provides a defence-in-depth layer. DEK/KEK envelope encryption for per-credential secrets.

## Section 1 — Backend API Audit

### ISSUE B-01
**Issue:** `GET /runs/{run_id}/debug-snapshot` returns all node outputs including credentials and API responses with no authentication guard.  
**Location:** `apps/api/app/routers/runs.py:run_debug_snapshot` (~line 719)  
**Severity:** Critical  
**Impact:** Anyone who knows or guesses a run ID can exfiltrate all node outputs, which can include plaintext credential fields, third-party API response bodies with tokens, and user-supplied PII.  
**Root Cause:** No `Depends(require_permission(...))` on the route. `NodeRun` has no `org_id` column so the ORM filter does not scope it.  
**Recommended Fix:** Add `dependencies=[Depends(require_permission("workflow:run"))]`. Verify that `_load_run_and_workflow` uses a filtered `select(Run)` not `session.get`.  
**Priority:** P0

### ISSUE B-02
**Issue:** MCP `delete_schedule`, `toggle_schedule`, and `cancel_run` tools use `session.get(Model, id)` which bypasses the `do_orm_execute` ORM tenant filter.  
**Location:** `apps/api/app/mcp/tools.py` — `_delete_schedule`, `_toggle_schedule`, `_cancel_run`  
**Severity:** Critical  
**Impact:** In multi-tenant mode, an authenticated user in Org A can delete/cancel resources belonging to Org B if they know the UUID. `session.get()` checks the identity map first, then queries by primary key without applying the `with_loader_criteria` added by `do_orm_execute`.  
**Root Cause:** SQLAlchemy's `session.get()` does not trigger the `do_orm_execute` criteria hook the same way `select()` does.  
**Recommended Fix:** Replace every `session.get(Model, id)` in MCP tools with an explicit `session.scalar(select(Model).where(Model.id == id, Model.org_id == active_org_id()))`.  
**Priority:** P0

### ISSUE B-03
**Issue:** `cancel_workflow_run` at `POST /runs/{run_id}/cancel` calls `cancel_run(run_id)` without first verifying the run belongs to the caller's org.  
**Location:** `apps/api/app/routers/runs.py:cancel_workflow_run` (~line 349)  
**Severity:** Critical  
**Impact:** In multi-tenant mode, an authenticated attacker in Org A can cancel a run belonging to Org B.  
**Root Cause:** `cancel_run(run_id)` is called directly with no DB lookup through a scoped ORM query.  
**Recommended Fix:** Before calling `cancel_run`, load the run with an explicit org-scoped select: `run = await session.scalar(select(Run).where(Run.id == run_id))`. Return 404 if `run is None`.  
**Priority:** P0

### ISSUE B-04
**Issue:** Unauthenticated `GET /workflows` and `GET /runs` list all workflows and runs when `auth_required=False`.  
**Location:** `apps/api/app/routers/workflows.py:list_workflows`, `apps/api/app/routers/runs.py:list_all_runs`  
**Severity:** High  
**Impact:** Default config (`auth_required=False`) allows any network-reachable caller to enumerate workflow names, run histories, statuses, and trigger types — a data exposure issue for any deployment that isn't fully private-network isolated.  
**Root Cause:** These GET routes have no `Depends(require_permission(...))` guard. The auth gate middleware applies a blanket block in required mode but individual routes don't independently require auth.  
**Recommended Fix:** Add at minimum `Depends(viewer_or_auth_required)` — a dependency that requires auth when `auth_required=True` and passes through when false.  
**Priority:** P1

### ISSUE B-05
**Issue:** `_api_token_principal` calls `await session.commit()` inside a FastAPI dependency, mid-request, to persist `last_used_at`.  
**Location:** `apps/api/app/security.py:_api_token_principal` (~line 177)  
**Severity:** High  
**Impact:** Commits any uncommitted state accumulated in the shared session by other dependencies that ran before the route handler. This is a session lifecycle violation that can cause partial writes to be committed prematurely.  
**Root Cause:** Using `commit()` instead of `flush()` to persist `last_used_at` within the shared session.  
**Recommended Fix:** Replace `await session.commit()` with `await session.flush()`. The transaction lifecycle is managed by `get_session`.  
**Priority:** P1

### ISSUE B-06
**Issue:** `_mark_interrupted_runs` at startup cancels ALL running/waiting runs including those executing on remote runner pools.  
**Location:** `apps/api/app/main.py:_mark_interrupted_runs` (~line 115)  
**Severity:** High  
**Impact:** In split topologies (API + separate workers), an API restart marks active remote runs as `cancelled`. Workers continue executing but their outputs are never persisted.  
**Root Cause:** The function filters by status but not by whether the run is local vs. remote-pool.  
**Recommended Fix:** Filter to only cancel runs where `Run.runner_pool_id IS NULL` (local runs). Remote-pool runs should only be recovered by lease expiry.  
**Priority:** P1

### ISSUE B-07
**Issue:** OAuth introspection endpoint is called synchronously per request with no caching or circuit breaker; 5-second timeout blocks every MCP request if the server is slow.  
**Location:** `apps/api/app/security.py:_external_oauth_principal` (~line 184)  
**Severity:** High  
**Impact:** A slow/unreachable OAuth server degrades all `/mcp` endpoint latency to 5+ seconds with cascading slowdown.  
**Root Cause:** No token-level cache; every request hits the introspection endpoint.  
**Recommended Fix:** Add a short-TTL LRU cache for `active=true` results (30–60s) and a circuit breaker after N consecutive failures.  
**Priority:** P1

### ISSUE B-08
**Issue:** SHA-256 is used directly to derive the Fernet key from `secret_key` with no KDF, no salt, and no domain separation between the signing and encryption uses of the same key.  
**Location:** `apps/api/app/services/crypto.py:_fernet` (~line 39)  
**Recommended Fix:** Use HKDF-SHA256 with distinct `info` strings for signing and encryption: `HKDF(algorithm=SHA256(), length=32, salt=None, info=b"noodle-credential-kek")`.  
**Severity:** Medium | **Priority:** P2

### ISSUE B-09
**Issue:** `decrypt_data(strict=False)` silently returns `{}` on decrypt failure. `list_credentials` uses this default and never reports misconfigured keys to operators.  
**Location:** `apps/api/app/services/crypto.py:decrypt_data`, `apps/api/app/routers/credentials.py:_info`  
**Recommended Fix:** In `_info()`, pass `strict=True` or add a warning log when `data` is empty but `encrypted_data` is set. Add a startup health check that round-trips one credential.  
**Severity:** Medium | **Priority:** P2

### ISSUE B-10
**Issue:** `_body_size_limit` middleware buffers the full request body in memory before passing it downstream. Up to 10 MiB per concurrent request, no per-IP budget.  
**Location:** `apps/api/app/main.py:_body_size_limit`  
**Recommended Fix:** Add a global concurrent-request body budget or `ConnectionLimitMiddleware`. Consider `request.stream()` for large uploads.  
**Severity:** Medium | **Priority:** P2

### ISSUE B-11
**Issue:** `list_credentials` for an org with 500 credentials across many orgs makes N sequential DB queries for org KEK fetches inside a loop.  
**Location:** `apps/api/app/routers/credentials.py:list_credentials`  
**Recommended Fix:** Batch-load all org KEKs with `select(Organization).where(Organization.id.in_(org_ids))` before the loop.  
**Severity:** Medium | **Priority:** P2

### ISSUE B-12
**Issue:** `list_all_runs` duplicates its WHERE clause between the count and data queries — adding a filter to one but not the other causes pagination bugs.  
**Location:** `apps/api/app/routers/runs.py:list_all_runs` (~lines 168–214)  
**Recommended Fix:** Extract shared filter conditions into `_build_runs_filter(...)` and apply to both statements.  
**Severity:** Low | **Priority:** P3

## Section 2 — Workflow Engine Audit

### ISSUE E-01
**Issue:** The Code node sandbox is not a real security boundary. Users can `import os`, `import socket`, `import subprocess`, read files, make network requests, and access environment variables.  
**Location:** `packages/nodes/noodle_nodes/builtin.py:_CodeValidator`, `_run_code_isolated`  
**Severity:** Critical  
**Impact:** Any editor-role user can execute arbitrary host OS commands, read secrets from environment variables, and exfiltrate data via network. The `_CODE_NODE_BLOCKED_IMPORTS` list and AST checks are explicitly documented as "steering guardrails, not a security sandbox."  
**Root Cause:** True sandboxing (seccomp, namespaces, container isolation) was deferred. Process-level isolation via `ProcessPoolExecutor` separates the coroutine but not the OS.  
**Recommended Fix:** For multi-tenant hosted deployments, enforce `execution_sandbox=required` routing Code nodes through Docker containers with security profiles. For self-hosted single-tenant, document the risk prominently. Add `os`, `socket`, `subprocess`, `urllib`, `pathlib`, `http` to the blocked imports list as a minimum guardrail.  
**Priority:** P0

### ISSUE E-02
**Issue:** `CodeExecToolAdapter` (the AI agent's built-in code execution tool) imports `subprocess` and may not route through the same process isolation as the Code node.  
**Location:** `packages/nodes/noodle_nodes/ai_v2/agent_tools.py:CodeExecToolAdapter`  
**Severity:** Critical  
**Impact:** LLM-generated code executed via the agent's code tool may run in the API process or a subprocess without the `ProcessPoolExecutor`/`_CodeValidator` isolation guarantees of the Code node. Combined with prompt injection (see E-07), an external data source could instruct the agent to execute OS commands.  
**Root Cause:** The AI agent's code execution tool is a separate code path from the engine's Code node.  
**Recommended Fix:** Confirm or enforce that `CodeExecToolAdapter.invoke_async` routes through the same `ProcessPoolExecutor` and applies `_CodeValidator` AST checks before execution. If it uses `subprocess.run` directly, apply the same isolation.  
**Priority:** P0

### ISSUE E-03
**Issue:** Cancellation is not propagated into `asyncio.to_thread` sync node execution. A cancelled workflow leaves its synchronous node running until completion.  
**Location:** `packages/core/noodle/engine/node_exec.py:invoke_node`  
**Severity:** High  
**Impact:** Long-running sync nodes (HTTP requests using `requests`, heavy ML computations, `wait_node`) continue consuming thread-pool slots and CPU/memory after the workflow is marked cancelled. Thread pool exhaustion can starve subsequent runs.  
**Root Cause:** Python threads cannot be interrupted mid-execution. `asyncio.CancelledError` on the task does not propagate into the worker thread.  
**Recommended Fix:** Implement a per-run `threading.Event` cancellation flag. Sync nodes should poll it at checkpoints. For the `wait_node`, use short-interval polling. Document that Code nodes running in threads cannot be cancelled cleanly.  
**Priority:** P1

### ISSUE E-04
**Issue:** DNS rebinding TOCTOU window in `safe_request` — resolution at validation time can differ from resolution at TCP connect time.  
**Location:** `packages/nodes/noodle_nodes/http_security.py:safe_request`  
**Severity:** High  
**Impact:** A DNS rebinding attacker can serve a public IP during validation, then flip to `169.254.169.254` before the TCP connection, enabling cloud metadata access from workflow nodes. The code acknowledges this as "residual risk."  
**Root Cause:** DNS resolution at validation time is not pinned for the actual connection.  
**Recommended Fix:** Implement a custom `requests` transport that connects to the validated IP directly (IP pinning). As an interim, require `sandbox_network` isolation for multi-tenant hosted deployments.  
**Priority:** P1

### ISSUE E-05
**Issue:** `index_urls` in venv backend config accepts arbitrary user-supplied PyPI index URLs without validation through the SSRF guard.  
**Location:** `apps/api/app/services/backends/venv.py:_do_build` (~line 54)  
**Severity:** High  
**Impact:** A user with environment creation privileges can specify a private network PyPI index URL to: exfiltrate package names (dependency confusion), serve malicious packages, or SSRF to internal services. `uv` makes its own HTTP connections bypassing `http_security.py`.  
**Root Cause:** Package installation is done via subprocess, bypassing the engine's HTTP security layer.  
**Recommended Fix:** Validate `index_urls` through `assert_public_http_url` before passing to `uv`. Allowlist permitted PyPI index URLs in system settings.  
**Priority:** P1

### ISSUE E-06
**Issue:** Cloud runner bootstrap token is embedded in EC2/GCE/Azure instance user-data and is accessible via IMDS from within the instance.  
**Location:** `apps/api/app/services/providers/agent.py:bootstrap_user_data`  
**Severity:** High  
**Impact:** A compromised instance immediately exposes its runner registration token. The code itself logs a `logger.warning` acknowledging this.  
**Root Cause:** User-data is the simplest bootstrap mechanism but is not secure for production.  
**Recommended Fix:** Use cloud-native secret distribution: AWS SSM/Secrets Manager with IAM instance role, GCP Secret Manager with service account, Azure Key Vault. Alternatively use short-lived one-time tokens that expire within minutes of instance start.  
**Priority:** P1

### ISSUE E-07
**Issue:** Prompt injection through tool results can trigger side-effecting tool calls despite a soft prompt-level instruction to ignore injected instructions.  
**Location:** `packages/nodes/noodle_nodes/ai_v2/agents.py:_tool_instruction`  
**Severity:** High  
**Impact:** External data sources (HTTP APIs, web search results, retrieved documents, MCP server results) can inject instructions into tool result content. With `side_effect_approval=auto_approve`, a crafted external response could instruct the LLM to call destructive tools.  
**Root Cause:** Relying on the LLM's instruction-following to reject prompt injection is not a reliable security boundary.  
**Recommended Fix:** Enforce `side_effect_approval=require_approval` as the default for any tool call triggered by a tool result. Add content guardrails or explicit tool result sandboxing patterns.  
**Priority:** P1

### ISSUE E-08
**Issue:** Sub-workflow cycle detection via `call_chain` frozenset is not propagated through remote runner dispatch, allowing remote cycles.  
**Location:** `packages/core/noodle/context.py:call_chain`, `apps/api/app/services/providers/agent.py:resolve_remote_subworkflow`  
**Severity:** High  
**Impact:** Workflow A on a remote runner calls workflow B which calls workflow A — creates an infinite recursive loop, consuming runner resources until OOM or timeout.  
**Root Cause:** `resolve_remote_subworkflow` restores `current_org_id` but does not restore `call_chain`.  
**Recommended Fix:** Pass `call_chain` (or the parent run's chain) in the `SubworkflowCall` payload and restore it in `resolve_remote_subworkflow`.  
**Priority:** P1

### ISSUE E-09
**Issue:** Loop iteration body uses a shallow copy of `node_outputs` — concurrent iterations can race on shared mutable objects within the output dicts.  
**Location:** `packages/core/noodle/engine/loops.py:_one_iteration`  
**Recommended Fix:** Use `copy.deepcopy` for iteration inputs when `concurrency > 1`, or document inputs as read-only and add a lint check.  
**Severity:** High | **Priority:** P2

### ISSUE E-10
**Issue:** `SandboxPool._read_event` silently drops malformed JSON lines — a fragmented `node_finished` event causes the worker loop to hang until timeout.  
**Location:** `apps/api/app/services/sandbox_pool.py:_read_event` (~line 142)  
**Recommended Fix:** Route container stdout to a separate channel from the protocol stream; add a counter and warning log for dropped lines.  
**Severity:** Medium | **Priority:** P2

### ISSUE E-11
**Issue:** `PooledProcessIsolator` creates up to 4 processes per environment with no global cap — N active environments creates 4N worker processes.  
**Location:** `packages/core/noodle/process_isolation.py:PooledProcessIsolator`  
**Recommended Fix:** Add a `max_total_workers` global limit; evict idle pools when the limit is reached.  
**Severity:** Medium | **Priority:** P2

### ISSUE E-12
**Issue:** `paginate()` in `ProviderTransport` has a 50-page cap but no item count cap — at 10,000 items/page, returns 500,000 items in-memory.  
**Location:** `packages/nodes/noodle_nodes/integrations_v2/transport.py:paginate`  
**Recommended Fix:** Add `max_items=10000` parameter; truncate with a warning log. Convert to a generator for streaming.  
**Severity:** Medium | **Priority:** P2

### ISSUE E-13
**Issue:** `max_iterations=0` in conditional loops silently runs 0 iterations instead of running with a default limit (what users likely intend).  
**Location:** `packages/core/noodle/engine/loops.py:_bounded_conditional_iterations`  
**Recommended Fix:** Treat 0 as "use default (1000)"; document and validate this in the node UI.  
**Severity:** Low | **Priority:** P3

## Section 3 — Frontend Audit

### ISSUE F-01
**Issue:** `signOut` function exposed as `window.__noodle_sign_out` global, bypassing React's component model and accessible to any page script.  
**Location:** `apps/web/src/App.tsx:156-164`  
**Severity:** High  
**Impact:** Any injected script or browser extension can force-logout the user. Not an auth bypass but an uncontrolled API surface.  
**Root Cause:** Used as a prop-drilling workaround.  
**Recommended Fix:** Move `signOut` into `AuthRuntimeProvider` context; `HomeHeader` can call `useAuthRuntime()` directly.  
**Priority:** P1

### ISSUE F-02
**Issue:** `marked.parse()` result is cast `as string` but the function can return `Promise<string>` in async configurations — produces `"[object Promise]"` in the chat panel rendered via `dangerouslySetInnerHTML`.  
**Location:** `apps/web/src/editor/ChatPanel.tsx:206`  
**Severity:** High  
**Impact:** Chat messages render as literal `"[object Promise]"` text when the async code path is taken — a broken core feature.  
**Root Cause:** Type cast used to paper over the `string | Promise<string>` union return type.  
**Recommended Fix:** Use `await marked.parse(text)` in an async function, or use `marked.parseInline()` (always synchronous).  
**Priority:** P1

### ISSUE F-03
**Issue:** Canvas `handleCanvasMouseDown` adds `mousemove`/`mouseup` listeners to `window` that are never removed if the component unmounts during a right-drag.  
**Location:** `apps/web/src/editor/Canvas.tsx:761-817`  
**Severity:** High  
**Impact:** Memory leak; stale closure listeners can mutate state after unmount causing React warnings and potential errors.  
**Root Cause:** Mouse listeners rely on the `onUp` closure for cleanup — if unmount fires before `mouseup`, cleanup never runs.  
**Recommended Fix:** Store listener refs in a `useRef` and add a `useEffect` cleanup (or use `AbortController` for all window listeners).  
**Priority:** P1

### ISSUE F-04
**Issue:** Module-level body-index cache (`_cachedBodyIndex`) in the Zustand store is mutable shared state not integrated with Zustand's immutable update model.  
**Location:** `apps/web/src/editor/store/index.ts:619-639`  
**Severity:** High  
**Impact:** Cache invalidation relies on object reference identity — spread-cloned state objects bust the cache unnecessarily on every state update, causing rebuild from scratch on every render pass.  
**Root Cause:** Module-level mutable state used as a memo substitute.  
**Recommended Fix:** Move the body-index cache into Zustand state as derived state, or use a `WeakMap` keyed on the state slice reference.  
**Priority:** P1

### ISSUE F-05
**Issue:** Credential form `values` state is not reset when the user switches credential presets — previous preset's field values remain in state and get submitted with the new type.  
**Location:** `apps/web/src/CredentialsPage.tsx:79-80`  
**Severity:** High  
**Impact:** Switching from Google OAuth to API Key preset submits OAuth tokens as the API Key data. Backend rejects but UX shows no error until after submission.  
**Root Cause:** `useState` is initialized once; switching `presetId` doesn't call `setValues(presetInitialValues(newPreset))`.  
**Recommended Fix:** In the preset change handler, also call `setValues(presetInitialValues(newPreset))`.  
**Priority:** P1

### ISSUE F-06
**Issue:** `requestAllPages` fetches all pages in parallel via `Promise.all` with no concurrency cap — hammers the API with N simultaneous requests on first load.  
**Location:** `apps/web/src/api.ts:271-302`  
**Recommended Fix:** Use a concurrency limit (max 3 simultaneous) or switch to server-side cursor pagination.  
**Severity:** Medium | **Priority:** P2

### ISSUE F-07
**Issue:** `NodeCard` subscribes to 10+ separate store selectors. Every streaming run event causes all NodeCards to re-evaluate their selectors.  
**Location:** `apps/web/src/editor/NodeCard.tsx:277-351`  
**Recommended Fix:** Combine run-state selectors into a single `useShallow` call keyed by `runKey`.  
**Severity:** Medium | **Priority:** P2

### ISSUE F-08
**Issue:** `hasTriggerUpstream` runs a full BFS traversal of the node graph on every NodeCard hover event (O(N+E)).  
**Location:** `apps/web/src/editor/NodeCard.tsx:216-242`  
**Recommended Fix:** Precompute `triggerReachableIds: Set<string>` as Zustand derived state, updated only when nodes/edges change. Each card checks `set.has(id)` in O(1).  
**Severity:** Medium | **Priority:** P2

### ISSUE F-09
**Issue:** Login form is built with `<div>` elements — no `<form>` wrapper, no `autocomplete` attributes, no semantic `type="submit"` button.  
**Location:** `apps/web/src/LoginPage.tsx:134-146`  
**Recommended Fix:** Wrap in `<form onSubmit>`, add `autocomplete="email"` and `autocomplete="current-password"`, use `type="submit"` button.  
**Severity:** Medium | **Priority:** P2

### ISSUE F-10
**Issue:** `NoodleNodeData` has `[key: string]: unknown` index signature that disables TypeScript's excess property checking on all node data objects.  
**Location:** `apps/web/src/editor/store/index.ts:67`  
**Recommended Fix:** Remove the index signature; add a separate `extraData?: Record<string, unknown>` field and make `unavailableType` an explicit optional property.  
**Severity:** Medium | **Priority:** P2

### ISSUE F-11
**Issue:** React Query global `retry: 1` retries 403 and 404 errors once, adding a 1-second delay before surfacing permission/not-found errors.  
**Location:** `apps/web/src/queries/client.ts:7`  
**Recommended Fix:** `retry: (count, error) => count < 1 && (!(error instanceof ApiError) || error.status >= 500)`  
**Severity:** Medium | **Priority:** P2

## Section 4 — Database & Migrations Audit

### ISSUE D-01
**Issue:** `runs.deduplication_key` has only a plain index — no UNIQUE constraint — allowing duplicate runs on concurrent webhook double-fire.  
**Location:** `apps/api/app/models.py:653` / migration `0025_run_dedup_key.py`  
**Severity:** High  
**Impact:** Two webhook deliveries trigger two parallel reads (both see "no active run for key"), both create runs, both commit — duplicate runs execute.  
**Root Cause:** Migration 0025 creates `ix_runs_deduplication_key` (plain), not a unique index. Application code does SELECT-then-INSERT, a classic TOCTOU.  
**Recommended Fix:** `CREATE UNIQUE INDEX uq_runs_deduplication_key ON runs (deduplication_key) WHERE deduplication_key IS NOT NULL`. Catch `UniqueViolation` on insert.  
**Priority:** P1

### ISSUE D-02
**Issue:** `workflow_versions` has no unique constraint on `(workflow_id, version)` — concurrent saves can produce two rows with the same version number.  
**Location:** `apps/api/app/models.py:1004–1027`  
**Severity:** High  
**Impact:** Version history integrity breaks; replay to a specific version becomes ambiguous.  
**Root Cause:** No `UniqueConstraint("workflow_id", "version")` in model or any migration. Version integer is incremented application-side.  
**Recommended Fix:** Add `UniqueConstraint("workflow_id", "version", name="uq_workflow_versions_workflow_version")` in a new migration.  
**Priority:** P1

### ISSUE D-03
**Issue:** `github_sync_jobs` table has no RLS policy — cross-tenant visibility of the sync job queue.  
**Location:** `apps/api/app/models.py:357–390` / migration `0059_github_sync.py`  
**Severity:** High  
**Impact:** Raw SQL paths, ops scripts, and direct psql sessions can read all orgs' sync job queue entries. Missing composite index on `(org_id, status, next_retry_at)` causes full-table scans on the hot worker query path.  
**Root Cause:** Migration 0059 was written after the batch RLS migration (0058) and did not include RLS installation for the two new tables.

## Recommended Architecture Improvements

### 1. Real Code Execution Sandbox (P0)
Current: `ProcessPoolExecutor` provides process separation but not OS-level sandboxing.  
Required: Route Code nodes through Docker containers with seccomp profiles, network isolation, and read-only root filesystem. The `execution_sandbox` config option already exists — make it mandatory for multi-tenant mode and enforce it in the `SandboxPool`.

### 2. Dedicated PostgreSQL Application Role
Create a `noodle_app` role with `NOSUPERUSER NOBYPASSRLS NOCREATEROLE`. Use it exclusively in the application connection string. This makes RLS fail-closed rather than fail-open.

### 3. Bulk Run Persistence
Replace sequential `session.add(NodeRun(...))` loops with `session.execute(insert(NodeRun), list_of_dicts)`. For loop-intensive workflows this is a 10–100x improvement in post-execution persistence time.

### 4. Server-Side Cursor Pagination
Replace `requestAllPages` offset-based fan-out with server-side cursor pagination (`?after=<cursor>`). Eliminates the N-parallel-requests pattern on first load and makes large workflow lists consistent under concurrent writes.

### 5. Queue N+1 Fix
`_org_fair_order` should batch-load org limits in one query before the dispatch loop. At 50+ concurrent tenants this is the dominant query in the hot path.

### 6. MCP Tool Org Isolation Pattern
Create a helper function `load_owned_resource(session, Model, id)` that wraps `session.scalar(select(Model).where(Model.id == id, Model.org_id == active_org_id()))` and returns `None` if not found. Replace every `session.get()` call in MCP tools with this helper.

### 7. Credential Encryption for GitHub Webhook Secret
Extend the DEK/KEK pattern to `GithubSyncConfig.webhook_secret`. The infrastructure is already in place — this is a 20-line change.

### 8. Production Web Image
Two-stage Dockerfile with `npm run build` → `nginx:alpine`. The CI can build and push this image on every merge to main.

## Final Verdict

### Is Noodle production-ready?

**For multi-tenant hosted deployment: No.** The Code node sandbox (P0), the MCP tool org isolation bypass (P0), and the GitHub sync RLS/encryption gaps (P1) must be fixed first.

**For single-tenant self-hosted deployment: Almost.** After fixing the 8 P0s (particularly the Docker image secrets, the web production image, the CI gates, and the debug snapshot auth), it is deployable for trusted users. The single-tenant threat model makes the multi-tenancy bypass issues self-inflicted.

### Biggest Risks

1. **Sandbox escape** — Editor users can exec host OS commands through the Code node. This is the most critical risk for any multi-user deployment.
2. **Secrets in Docker image** — If `deploy/.env` was ever baked into a pushed image, both production keys are compromised.
3. **CI blind spots** — Frontend tests not running in CI means regressions can ship silently on every merge.
4. **GitHub sync data exposure** — Two tables with sensitive data missing RLS, and a webhook secret in plaintext.
5. **MCP tool cross-tenant operations** — Authenticated users can delete other orgs' schedules and cancel other orgs' runs.

### What to Fix First

1. The `deploy/.env` secret rotation and Docker build fix (can be done in hours)
2. The 3 MCP `session.get()` org isolation bypasses (30 minutes of code change)
3. Auth guard on debug snapshot endpoint (5 minutes)
4. Wire frontend tests into CI (10 minutes)
5. Code node blocked imports expansion + `CodeExecToolAdapter` audit

### What Can Wait

- DNS rebinding mitigation (affects multi-tenant hosted only, mitigated by network isolation)
- HKDF key derivation (theoretical risk with strong keys)
- NodeRun float timestamps (cosmetic)
- ReactFlow canvas unit tests (important but not production-blocking)
- Workflow import endpoint (missing feature, not a blocker)

### What I Would Personally Refactor First as Principal Engineer

The Code node sandbox design is the one thing I'd block everything else on. The current `_CODE_NODE_BLOCKED_IMPORTS` + `_CodeValidator` approach is documented in its own comments as "not a security sandbox" — that comment being in production code is a sign the team knows it but hasn't had time to fix it. Making the Docker execution path (`SandboxPool`) the mandatory path for Code nodes in multi-tenant mode is ~1 week of work (the Docker infrastructure already exists) and it unlocks the ability to actually market this as a hosted platform to paying users.

The second thing I'd fix is the CI configuration — not because the code is bad, but because right now you have a false sense of green CI when frontend regressions, Postgres bugs, and CVEs all pass through silently. A red CI is a gift: it means you caught something before a user did.
