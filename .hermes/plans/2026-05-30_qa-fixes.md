## P0 — Critical (server stability / security)

### P0-1  Code node CPU-bound infinite loop hangs entire server

**Root cause:** `DEFAULT_NODE_TIMEOUTS["code"] = 60.0` exists in
`packages/core/nodyra/engine.py` but `asyncio.wait_for(..., timeout)` on a
`to_thread(sync_fn)` cannot interrupt a CPU-spinning Python thread — the
thread keeps running and holds the event loop worker. The 60 s timeout fires
in asyncio but the thread is zombie until the process dies.

**Fix:** In `packages/core/nodyra/engine.py`, wrap sync node execution in a
`concurrent.futures.ProcessPoolExecutor` (or a subprocess) for nodes whose
type is in `SANDBOXED_NODE_TYPES = {"code"}`. Process-level execution lets
the OS `SIGKILL` the child after `timeout` seconds via
`asyncio.wait_for(..., timeout)` + `executor.shutdown(cancel_futures=True)`.
Fallback: use `multiprocessing` directly with `Process.kill()` after a
`timeout` join.

**Files:**
- `packages/core/nodyra/engine.py` — add process-pool path for `code` nodes
- `packages/core/nodyra/nodes/code.py` (or wherever code exec lives) — ensure
  the exec context is picklable / can run in a child process
- `apps/api/app/config.py` — add `code_node_timeout_seconds: float = 30.0`

**Test:** `packages/core/tests/test_engine.py` — add test: code node with
`while True: pass` must fail with TimeoutError within ~35 s.

### P0-2  Large Code node output silently crashes the runner

**Root cause:** `_cap_output` in `apps/api/app/services/runner.py` truncates
output but the crash happens *before* that — during serialisation of a
`list(range(100_000))` in the engine result before it reaches `runner.py`.

**Fix:** In `packages/core/nodyra/engine.py`, after a node returns its output,
measure `len(json.dumps(output, default=str))` (or use `sys.getsizeof`
recursively). If > `MAX_NODE_OUTPUT_BYTES` (default 5 MB, configurable), raise
`NodeOutputTooLargeError` with a clear message. Catch this in the engine's
error handler the same way `TimeoutError` is caught (line ~411).

**Files:**
- `packages/core/nodyra/engine.py` — add output size guard after node return
- `apps/api/app/config.py` — `max_node_output_bytes: int = 5_000_000`

### P0-3  No rate limiting — `/auth/login` brute-force risk

**Root cause:** `main.py` has no rate-limit middleware. `slowapi` is not
installed.

**Fix:**
1. Add `slowapi` to `apps/api/pyproject.toml` dependencies.
2. In `apps/api/app/main.py` add a `Limiter` with
   `key_func=get_remote_address`.
3. Apply `@limiter.limit("10/minute")` to `POST /auth/login` and
   `POST /auth/register` in `apps/api/app/routers/auth.py`.
4. Add global `RateLimitExceeded` handler returning 429.

**Files:**
- `apps/api/pyproject.toml`
- `apps/api/app/main.py`
- `apps/api/app/routers/auth.py`

### P0-4  WebSocket `/ws/runs/{run_id}` returns HTTP 403 for all clients

**Root cause:** The global auth middleware in `main.py` intercepts the WS
upgrade request before it reaches the route handler. The middleware checks
for a Bearer token in the `Authorization` header — but browsers/WS clients
send the token as a query param (`?token=...`). The middleware rejects the
request with 403 before the route's own `verify_token(query_params["token"])`
logic can run.

**Fix:** In `apps/api/app/main.py` (or wherever the auth middleware lives),
add `/ws/` paths to the exempt path set (similar to how `/metrics` and
`/system/status` are already exempt). The route handler already does its own
token validation via `verify_token(websocket.query_params.get("token"))`.

**Files:**
- `apps/api/app/main.py` — add `"/ws/"` prefix to `_AUTH_EXEMPT_PATHS`

### H-7  `artifacts_api` in Code node causes silent engine crash

**Root cause:** `artifacts_api` is injected as a kwarg into the code node
executor, but something in the pickling / subprocess handoff fails silently
when the process-pool fix (P0-1) is applied. Even without that, the current
inline exec appears to swallow the NameError at the engine level.

**Fix:**
1. Ensure `artifacts_api` is always injected into the `exec()` locals dict
   when running a code node, even if the artifact backend is unavailable
   (inject a no-op stub that raises a clear `RuntimeError("artifact backend
   not configured")`).
2. Any exception escaping the `exec()` call should be caught and re-raised as
   `NodeExecutionError` with full traceback string.

**Files:**
- `packages/core/nodyra/nodes/code.py` (or wherever `exec()` is called)
- `packages/core/nodyra/engine.py` — ensure exception propagation

## Risks & Notes

- **Process-pool for code nodes** adds ~100–300 ms cold-start per run. For
  short nodes this is noticeable. Mitigate with a pool (pre-warmed workers).
- **Pagination envelope** is a breaking API change. If any frontend code does
  `response.map(...)` directly it will break. Search `apps/web/src` for all
  `GET /nodes`, `GET /runs`, `GET /workflows` callers and update them.
- **Alembic migrations** must run before the new API container starts. The
  `deploy/docker-compose.yml` uses a `command: alembic upgrade head && uvicorn
  ...` pattern — verify this is still the entrypoint.
- The **engine lives in `packages/core`** which is a separate uv workspace
  package. Rebuilding requires the `api` Docker image (which installs it), not
  just `web`.
